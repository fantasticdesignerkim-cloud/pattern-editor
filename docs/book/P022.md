# P.22 — 목둘레 턱 Ⓘ «밑단 폭을 1cm 추가, 다트를 닫아 목둘레를 벌린다»

> **출처: [패턴학교]** P.22 (`books/pages/p022.jpg`, 읽기 전용) + 처리 방법 P.161(꼬리말 «닫는다·벌린다…P.161»).
> 판독·구현 2026-10-03. **상태: ✅ 구현 완료**. 책이 수치로 주지 않는 세 가지는 **사용자 확정**(아래). 실행 수치의 단일 진실은 `js/bodicePresets.js` 의 `bunka-bodice-I` 레코드.

## 책에서 읽히는 것 (확정)
- 본문: «원하는 목둘레의 위치에 절개선을 넣어 벌린다. 방법은 AH 다트와 뒤 어깨 다트를 닫아 **벌어지는 치수만큼 목둘레를 벌린다.**»
- 기준 몸판: 제목 «밑단 폭 1cm 추가» + 캡션 «실루엣은 Ⓑ 와 같은 단정한 박스형» → **Ⓑ**(`hemSideOffsetCm: 1`). 도해에 허리 다트가 없다 → `waistDartScales` 0(Ⓖ·Ⓗ 와 같은 규약).
- 대상: **앞(AH 다트, 피벗 BP) · 뒤(어깨 다트)** 둘 다. «※ 뒤도 같은 방법으로 잘라서 벌린다».
- 연산 161: 다트를 **닫고** 그 **반동**으로 지정한 곳(목둘레)을 벌린다. 절개선 = 피벗 → 목둘레, 부채꼴로 열린다.
- 도해: 앞 절개 그림에 피벗에서 목둘레로 가는 절개선 **둘**, 목둘레에 턱 두 곳, «2» 표기 + «박기 끝»(턱을 박는 끝점은 목둘레에서 짧게 내려온 곳). 뒤도 같다.
- 사진 캡션: «턱을 꺾는 방향은 앞뒤 모두 **바깥쪽**. 턱 분량은 전체적으로 조금 적게.»

## 책에 없어 **사용자가 확정**한 것 (2026-10-03, 질문 1건으로 확정)
1. **절개 위치** = 목둘레 호 길이의 **1/3·2/3** 지점(앞·뒤 각 2개). 피벗(앞 BP · 뒤 어깨 다트 꼭짓점)에서 직선으로 긋는다.
2. **분량 배분** = 닫는 다트각 θ 를 두 절개가 **균등(각 θ/2)** 으로 나눈다 — 중심을 품은 조각 고정, 어깨 쪽 조각 θ, 가운데 조각 θ/2(강체 회전). 각이 같으므로 틈의 현은 **절개 길이에 비례**해 달라진다(앞 3.426 + 3.098). 사진 캡션의 «조금 적게» 는 **적용하지 않고** 닫은 양 전부를 쓴다.
3. **턱 깊이(박기 끝)** = 절개 다리를 따라 목둘레에서 **2cm 아래**. 턱 방향은 **바깥쪽**. 둘 다 **표시 전용** — geometry 에 만들어 넣지 않는다(메타·제작 정보에만).

## 산식 · 실측 (B83·W64)
- 틈 현 ∅ᵢ = 2·Lᵢ·sin(θ/4), Lᵢ = 피벗→절개 끝(목둘레) 거리. 총 벌림 = ∅₁ + ∅₂.
- 앞: θ=18.25°(각 9.125°) · L 21.532 / 19.471 → ∅ 3.426 + 3.098 = **6.524cm** · 목둘레 호 11.130cm(1/3씩 3.710).
- 뒤: θ=11.38°(각 5.69°) · L 10.077 / 10.963 → ∅ 1.000 + 1.088 = **2.088cm** · 목둘레 호 7.693cm · 어깨 잔여 sliver 0.103cm(Ⓖ 와 같은 값, 감추지 않고 기록).
- 봉제 목둘레 = 세 호의 합 = Ⓑ 의 원래 목둘레(틈은 접혀 사라진다). 그래서 `piece.necklineLenCm` 에 그 합을 실어 계측·카라가 한 조각만 재지 않게 한다(앞 11.1 · 뒤 7.7 · 반패턴 18.8cm — Ⓑ 와 같다).

## 엔진 재사용 판정 (엔진 책임 경계)
- `dartMove`·분할 엔진(심장 5함수) **건드리지 않았다.** `designFlare.closeDartSpread` 는 절개 하나·`hemEdge:"hem"` 전용이라 **직접 재사용 불가** — 같은 파일에 `designFlare.neckTuck`(ring 분할 `designLineTool.buildPieceRing`·`extractArc`·강체 회전 재사용)을 **접착 코드로 추가**했다. 새 엔진 아님.
- 결과 외곽은 **apex 까지 열린 V 두 개**를 가진다(열린 다트 = 현재 외곽선 · 젤리 모델). 틈의 두 다리는 `dart:{id:"neck-tuck-1|2", boundary:"neckline", apexAt}` 로 선언 — 체크포인트의 외곽 연결성 판정(차수>2 정점은 선언된 다리만 허용)이 읽는다.
- ★ **틈 다리에 `edge` 이름을 주지 않는다.** `designRenderer` 의 `EDGE_PLACEMENT` 는 닫힌 어휘라 새 이름(`tuck-slit`)이 `bad-edge` 로 **렌더를 깼다 — 헤드리스 하네스는 통과하고 브라우저에서만 터졌다**(실제 브라우저로 잡음). 회귀: `neckTuckPresetCheck` §5b 가 `DR.createWorkingGroup` 으로 막는다.
- 기존 프리셋 geometry 는 `body.neckTuck` 이 없으면 새 경로를 호출하지 않는다 → Ⓐ~Ⓥ 18종 sha **HEAD 와 바이트 동일**(HEAD 트리에서 측정해 테스트에 고정).

## 남은 위험 (설계 변경 아님)
- 틈은 apex 까지 열려 있고(가운데·어깨 조각이 BP 한 점에서만 이어진다) **봉제 정합(박기 끝 아래 처리·턱 접힘선)은 패턴선 확정 몫**이다. 목둘레의 «완만한 곡선»(P.157 공통 불변식)은 틈 때문에 적용하지 않았다.
- 시맨틱 증거(`evaluateSemantics`)는 틈 다리에 `attach` 가 없어 `dart-attachment-missing` 을 낸다(완료 차단 아님 — Ⓖ 도 `dart-attachment-misaligned`).
- 앞 틈 합 6.5cm 는 «조금 적게» 라는 책 설명보다 크다(닫은 양 전부 사용을 사용자가 확정). 필요하면 후속으로 감소율 파라미터를 열 수 있다.
- 가슴·허리 계측은 중심(하체) 조각이 고정이라 유효하다(가슴 완성 94.7 · 허리 완성 91.4 — 허리 다트를 0 으로 둔 결과).
- Ⓙ(P.23) 미판독.
