## 책에서 읽히는 것 (확정)
- 머리말: «앞 AH 다트와 뒤 어깨 다트를 닫아 목둘레를 벌린다.» 제목: «밑단 폭을 1cm 추가».
- 기준 몸판 = **Ⓑ**(`hemSideOffsetCm:1`) — 사진 캡션 «실루엣은 Ⓑ 와 같은 단정한 박스형», 도해 밑단 «1». 허리 다트 없음(`waistDartScales` 0, Ⓘ·Ⓙ 와 같은 규약). 도해 «Ⓐ 의 패턴» 표기는 몸판 계통 안내.
- 대상: **앞·뒤 둘 다**(«※ 뒤도 같은 방법으로 잘라서 벌린다»). 닫는 다트 = 앞 AH(BP) · 뒤 어깨 다트 — Ⓘ·Ⓙ 와 같다. 다트는 **끝까지 전부 닫는다**(«닫는다» 도해).
- **절개 = 앞·뒤 각 1개**(Ⓘ 는 2개). 도해(앞·뒤·절개 그림 모두)에 피벗 → 목둘레로 가는 절개선 하나, 벌어진 V 쐐기 하나. 벌어진 치수: 앞 **●**, 뒤 **∅**.
- **절개 위치 숫자**: 뒤 **«3»**, 앞 **«4»**(절개 그림에도 «4»). 지시선이 SNP 쪽 목둘레에서 시작해 **절개가 목둘레에 닿는 지점**에서 끝난다 → *SNP 에서 목둘레 호를 따라 앞 4cm · 뒤 3cm 지점에 절개* 로 읽었다. (※ 이 읽기가 아래 질문의 전제.)
- **개더 분량(캡션, 확정)**: «개더 분량은 **뒤는 ∅의 약 0.5배, 앞은 ●의 약 1배**.» 도해 주기: 앞 «개더(●치수로 줄인다)» · 뒤 «개더(∅치수로 줄인다)». 즉 벌어진 만큼의 길이를 개더로 소화한다 — 앞은 벌린 만큼 전부(●×1), 뒤는 절반(∅×0.5).
- 개더 형상: 절개 그림에서 개더는 쐐기 입구 위에 점선 파도로 표시된 **표시**이며 geometry 가 아니다(Ⓡ~Ⓥ 의 «개더 = 쐐기·띠, 주름 수는 책에 없다» 선례와 같다).
- 사진: 앞·뒤·옆 모두 목둘레 전체에 걸친 개더(어깨 쪽 SNP 부근은 거의 평평).

## 산식 (책 + 이미 확정된 규칙으로 읽은 것)
- 한 절개가 θ(닫는 다트각, 앞 18.25° · 뒤 11.38°) 전부를 벌린다 → 틈 현 ∅ = 2·L·sin(θ/2), L = 피벗 → 절개 끝(목둘레) 거리. 총 벌림이 절개 하나에 몰리므로 Ⓘ(θ/2 두 곳)와 틈 값이 다르다.
- 개더로 줄이는 길이: 앞 R_f = ●×1.0, 뒤 R_b = ∅×0.5. 봉제 목둘레 = (Ⓑ 원래 목둘레 L_neck) + 틈 현 − R → 앞 L_neck 11.13 / 뒤 7.69 (앞은 원래와 같고 뒤는 L_neck + 0.5∅).
- 정밀 수치(L·●·∅)는 구현 때 실측해 기록한다 — 지금은 계산하지 않았다.

## 엔진 재사용 판정
- `designFlare.neckTuck` 은 절개 위치가 모듈 상수 `TUCK_AT=[1/3,2/3]`·균등 θ/N 로 **고정**이라 그대로는 못 쓴다. 최소 변경 = 같은 함수에 **opts.cuts**(SNP 로부터의 호 길이 목록) 확장을 추가하고, 옵션이 없으면 기존 경로 그대로(Ⓐ~Ⓙ **바이트 동일** 유지). 링 분할·강체 회전·열린 V 외곽·`dart:{id,boundary:"neckline",apexAt}` 선언은 그대로 쓴다. 새 엔진 아님, `dartMove` 심장 5함수 무관.
- `centerBand`(Ⓙ)는 **쓰지 않는다** — 중심 평행 띠는 턱 분량 추가이고, 개더는 중심을 옮기지 않는다. 턱(박기 끝·접는 방향 표시)과 개더(개더 구간·줄이는 분량 표시)의 **표시 의미를 섞지 않는다**: Ⓚ 메타는 `neckTuck` 이 아니라 별도 `neckGather` 로 둔다.
- 기존 개더 구현(Ⓡ~Ⓥ 의 `yokeGather`·`peplumAnnotation`)은 **띠/쐐기 + 문구**일 뿐 목둘레 개더 구간 개념이 없다 → 재사용 대상은 «표시 전용 문구/토글 규약» 만.

## ✅ 사용자 확정 (2026-10-04, 질문 1건)
**개더 구간 = B안**: 절개 지점(어깨 쪽 다리 끝)부터 앞·뒤중심까지 전부, SNP 쪽 앞 4cm·뒤 3cm 만 제외. 책에 양끝 수치가 없어 확정값이다. geometry(절개 1개·θ 전부 닫음)는 A·B 안이 같고 개더 구간은 메타·표시·검산에만 쓴다.
