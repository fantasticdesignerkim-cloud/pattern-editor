## 허리 다트 배분 (`js/draft.js` 의 `darts` 블록)

총 다트량 `total` 에 아래 비율을 곱해 여섯 곳에 배분한다. **합계 정확히 100%.**

| 기호 | 비율 | 위치(코드 주석 그대로) | 성격 |
|---|---|---|---|
| **a** | **14%** | BP 아래 | 앞 봉제 다트 |
| **b** | **15%** | F점 1.5cm 전중심쪽 | 앞 봉제 다트 |
| **c** | **11%** | 옆선 | **봉제 다트가 아니다** — 앞·뒤 옆선에 나눠 붙는 허리 조임 |
| **d** | **35%** | 뒤품선~옆선 1cm 뒤중심 | 뒤 봉제 다트 |
| **e** | **18%** | E점 0.5cm 뒤중심 | 뒤 봉제 다트 |
| **f** | **7%** | 뒤중심 | **봉제 다트가 아니다** — 뒤중심 접어재단 자리의 조임 |

### 기준 치수(B 83 · W 64 · BL 38)에서의 실측값

총 다트량 **12.5** 기준 — a 1.75 · b 1.875 · c 1.375(앞뒤 0.6875씩) · d 4.375 · e 2.25 · f 0.875.

- **봉제 다트 합(a·b·d·e) = 10.25** ← 디자인 단계 `허리 다트량` 입력이 가리키는 값
- 반패턴 조임 합 = 12.0625 (`f` 는 접힘선 위 반쪽이라 반패턴에 0.4375 만 나타난다)
- 완성 허리 = (47.5 − 12.0625) × 2 = **70.875** (= W + 6.875)

### 가슴 여유

BL 외곽 둘레 **95 = B 83 + 12**. ([패턴학교] P.14 의 "가슴둘레 여유분 12cm" 와 같다.)

## 코드에서 c·f 가 구분되는 방식

원형이 만들어 내는 dart 메타데이터가 성격을 이미 구분한다 — **이름이 아니라 플래그로** 구분되므로
재배분 대상 선별이 안전하다.

- `c` → `locked: true`, `group: "side-waist-c"` (앞·뒤로 나뉜 한 논리 다트)
- `f` → `onFold: true`, 다리 1개(`legCount: 1`), `intakeCm: null`
- `a·b·d·e` → 위 둘 다 아님, 다리 2개

**주의**: `f` 는 `intakeCm` 이 `null` 이라 **단순 intake 합산에서 조용히 빠진다.** 완성 둘레를
계산할 때는 다리↔접힘선 거리로 따로 세어야 한다(실제로 한 번 0.875cm 를 놓쳤다 —
`bodiceCheckpoint.girthMeasure` 가 이걸 처리한다).

## [패턴학교] 와 다른 점 (확정)

| | [학교책] (우리 원형) | [패턴학교] (P.130) |
|---|---|---|
| 총 다트량 공식 | — (입력값 12.5) | `(B/2 + 6) − (W/2 + 3)` → 12.5 **동일** |
| a·b·d·e 비율 | 14 / 15 / 35 / 18 | **동일** |
| c(옆선 11%) · f(뒤중심 7%) | **쓴다** | **없다** |
| 실제 사용 비율 | 100% | **82%** |

→ 같은 총량·같은 네 비율이고, **차이는 `c`·`f` 사용 여부뿐**이다. [패턴학교]의 원형은
박시 라인(옆선 수직)이라 허리를 덜 잡는다. 자세한 대조는 [P130.md](P130.md).

## 결정 (2026-09 사용자 확정)

- **우리 원형은 [학교책]의 a~f 를 유지한다.** [패턴학교]에 맞춰 `c`·`f` 를 없애지 않는다 —
  원형 형상이 바뀌어 완료본 hash·shape 골든이 전부 무효가 된다.
- 디자인 단계의 **허리 다트 재배분 대상은 봉제 다트 `a·b·d·e` 뿐**이고, 배분 기본값은
  [학교책] 비율(= [패턴학교]와 같은 14/15/35/18)을 균일 배율로 유지한다.
- `c` 는 옆선 도구(`waistSideOffsetCm`)가 이미 움직이므로 재배분에 넣지 않는다(과결정).
  `f` 는 뒤중심 접어재단과 얽혀 고정한다.

## 미확정

- **완성 허리 70.875 vs 공식이 뜻하는 70**(= W+6) 의 0.875 차이가 [학교책]의 의도인지
  우리 구현의 해석인지 **확인하지 않았다.** `f` 의 반쪽 처리에서 나온다.
- 위 비율·성격 전부 **원본 대조 전**이다(코드에서 역추출).
