## 3. 소매 완료 → 카라 → `designResult` (26종 전부 통과)

- **소유권**
  - `designResult.bodice` = 원래 `bodiceResult`(같은 참조·바이트 동일). 파생 몸판으로 덮어쓰지 않는다.
  - `designResult.sleeve` = 그 소매 완료본(출처 `origin.presetId` 보임).
  - Ⓡ~Ⓩ 파생 몸판은 `sleeve.derivedBodice` 에만 있다(작업 상태와 바이트 동일). Ⓐ~Ⓠ 는 이 필드가 없다.
- **hash**
  - 26 소매 → `sleeveHash` 26개, `designResult.hash` 26개가 서로 다르다.
  - Ⓡ~Ⓩ 서명에는 파생 몸판 형상이 들어 있다(변조하면 «변경됨»).
- **Ⓨ·Ⓩ**: 소매 조각이 없다(`sleevePiece:false` · 빈 버킷). **Ⓧ**: 소매 버킷 = 덧천 한 장.
  셋 모두 cap 은 «적용 안 함»이다. 그래도 `designResult` 는 완료된다 — 완성 불가가 아니다(별도 소매 조각이 없는 형태다).
- **카라와의 관계.** 카라는 원래 `bodiceResult` 목둘레에서 제도된다(형상 source). 소매는 작업 순서 게이트일 뿐이다.
  - 파생 몸판에서 목둘레 봉제 길이를 다시 쟀다: 파생 몸판 앞·뒤 목 + 소매의 목 구간.
  - 9종 모두 원래 값 **18.8227 과 같다**. 래글런 Ⓥ·Ⓦ 는 몸판 12.548 + 소매 6.274 로 나뉜다.
  - 그래서 카라 **길이 책임**은 유지된다. 맞춤점 위치는 아래 §8 의 «재단 전» 항목이다.

- **차단**(`reject` 가 있는 24종): 소매 완료 불가 · 기존 완료본 보존.

  - R–Z: `bodice-not-a` 차단 · 소매 완료 불가. **원래 몸판으로 몰래 되돌리지 않는다.**

**UX 관찰.** Ⓩ 에서 소매길이를 13 으로 고친 뒤 계열을 스트레이트로 바꾸면, 공용 소매길이 칸은 **사용자가 고친 값 13 을 유지**한다(정해진 동작).

### 최종 몸판 · 절개선 재검증 (`js/designResult.js` — #2)

**승인 원칙(김님 «오키오키» · Codex 권장안):**

- 재단이 읽을 «현재 몸판» = 소매 작업까지 반영한 최종 형상이다. `sleeveResult.derivedBodice` 가 있으면 그것, 없으면 `bodiceResult`.
- 절개선은 이 최종 몸판에서 다시 검증한다. 원래 몸판에서 유효했어도 최종 몸판에 맞지 않으면 **사유를 보이고 `designResult` 완료를 거부**한다.
- 자동 회전·이동·삭제·조용한 제외로 통과시키지 않는다.

**구현(최소):**

- `designResult.finalBodiceOf({ bodice, sleeve })` — 공용 조회 경계. `{ source: "sleeve-derived" | "bodice", front, back }` 를 돌려준다.
  - `front`/`back` 은 이미 frozen 인 `sleeveResult.derivedBodice` 또는 `bodiceResult` 조각을 **그대로 가리킨다.** 복제·새 저장 필드는 없다.
  - `sleeveHash` 가 파생 몸판 외곽을 이미 서명하므로 `designResult.hash` 가 최종 몸판을 덮는다. hash 밖 참조 필드를 따로 두지 않았다.
- 절개선 3분류(같은 `designLineTool` 판정):
  1. 최종 몸판에서 유효 → `structuralLines` 에 포함.
  2. 원래 몸판에서는 유효했지만 최종 몸판에서 무효 → **거부** `cut-invalid-on-final-bodice`. `check().cutRejects = [{ piece, lineId, reason }]`.
  3. 원래·최종 모두에서 무효 → 작성 중·미완성 선. **기존 계약 그대로 제외**(차단 아님).
- 파생 몸판이 없으면(Ⓐ~Ⓠ) 이전과 **똑같은 호출**(`gatherValidCuts(patternLines, bodiceResult)`)이다.
- 무효화는 같은 기준을 쓴다. `isCurrentDesignChanged` 가 같은 `check()` 를 부르므로 소매·몸판·절개선 변경이 모두 같은 최종 몸판 판정으로 «변경됨/거부»가 된다.
- UI(`ui.js`): 거부 사유를 구체적으로 보인다. 예(실제 화면 문구):
  «완료 전 검사: 절개선이 소매까지 반영한 최종 몸판에 맞지 않음(소매 Ⓩ 파생 몸판 기준) — 앞판 절개선 line-1: 절개선 중간이 외곽선에 닿음 · 원래 몸판에서는 맞던 선입니다 · 몸판 탭에서 그 절개선을 고치거나 지운 뒤 다시 완료하세요»
