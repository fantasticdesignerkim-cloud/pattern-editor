## 1. 나쁜 소식 (먼저)

**① 실물 증거 0벌.**
문제: 원형·디자인·재단·DXF·A4 인쇄까지 연결됐지만 Optitex 실물 검수(여밈·안단 좌우, 소매·커프스 좌우, C.F/C.B, I자 3mm 너치, 주머니)가 전부 «대기»다.
해결: «종이 위에 있다»가 제1법칙이면, 종이와 원단 위에서 통과해야 끝난 것이다.
다음 단계: 형건님 검수 날짜를 이번 주 안으로 확정해 주세요. 그 전에는 새 기능 착수 금지.

**② 미커밋 52파일 · +781/−940줄.**
문제: 미저장 변경 보호·버전 검사 공통화가 «로컬 검증 완료»인데 커밋이 안 돼 있다. 노트북 하나가 망가지면 같이 사라진다.
해결: 두 묶음을 각각 커밋·푸시한다(엔진·UI 분리 규칙대로).
다음 단계: 오늘 커밋 승인 부탁드립니다.

**③ 피드백 루프가 느리다.**
문제: 전체 회귀(`runAll.js`, 하네스 173파일)가 10분을 넘긴다. 한 번 고치고 확인하는 데 10분이면 하루 반복 횟수가 정해진다.
해결: 빠른 묶음(골든 + 지금 만지는 영역, 1분 이내)과 커밋 전 전체 묶음으로 나눈다.
다음 단계: 승인 시 스위트 실행 시간 측정 → 상위 10개 느린 파일부터 정리.

**④ 임시 코드가 제품에 남아 있다.**
문제: `js/tempDefaultCurve.js`(TEMP 기본 곡선, 2026-10-06)가 아직 `index.html`에서 로드되고 제거 날짜가 없다. GOAL.md 도 비어 있다.
해결: 임시는 날짜가 없으면 영구가 된다. 제거 조건 1줄 + 날짜를 정한다.
다음 단계: «셔츠 1벌 실물 검수 통과 시 제거»로 묶을지 결정 부탁드립니다.

**⑤ 넓이가 깊이를 앞질렀다.**
문제: 몸판 변형 22, 소매 Ⓐ~Ⓩ 26, 칼라 여러 종이 있지만 실사용 검증된 경로는 «박시 Ⓐ + 소매 Ⓐ(+커프스) + 칼라 M» 한 줄뿐이다.
해결: 한 벌이 끝까지 가는 경로 하나를 «금(金) 경로»로 정하고, 나머지는 그 경로에서 깨진 것만 고친다.
다음 단계: 실물 봉제(2026-11-27)에서 나온 불편만 다음 작업 목록으로 삼는다.
(정정: 초안에 «커프스 독립 조각 없음»이라 썼으나 틀렸다 — `js/designCuff.js` · `a40b3a0` · `82c0d8f` 로 커프스 조각·좌우 쌍 DXF 가 이미 있다. 11-10 작업표 §8 은 옛 기록.)

## 4. 페이지 2(DOROBO 재단 사이트) — 3문장

1. **문제**: 패턴이 나와도 원단 위에 어떻게 놓고 몇 야드 쓰는지는 재단사 손에 있다 — 여기가 원가가 새는 곳이다.
2. **해결**: 별도 사이트로, 입력은 오직 페이지 1의 DXF(조각 이름·식서·수량·시접선/완성선 레이어·너치)다. 씨앗은 이미 있다(`js/cutMarker.js` — 천 폭·정밀 겹침·야드 계산).
3. **다음 단계**: 코드보다 **연결 계약(DXF 의미 명세) 1장**을 먼저 확정한다. 계약이 굳어야 두 사이트가 서로를 깨지 않는다.

**페이지 2 순서 (자동화는 마지막)** — 머스크 5단계를 그대로 쓴다
1. 요구사항 의심: 처음엔 셔츠 1벌 · 천 폭 1종 · 원단 1종만.
2. 지우기: 자동 배치(nesting)는 v1에서 뺀다.
3. 단순화: 수동 배치 + 식서 고정 회전 + 겹침 경고 + 요척(야드) 숫자.
4. 가속: 재단사가 실제로 배치하는 시간을 재서 줄인다.
5. 자동화: 수동 배치 기록이 쌓인 뒤에 자동 배치. ← 이 순서를 바꾸면 안 된다.

**착수 조건(blockedBy)**: 페이지 1 완료 기준 5개 충족 + DXF 의미 명세 승인.
