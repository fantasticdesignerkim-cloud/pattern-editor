# 표준 절차 — 교재의 라인·변형 하나를 기능으로 만들기

> **왜 있나**: 남은 교재가 4권(바지·코트·자켓·원피스·스커트)이다. 매번 "어떻게 할지"를 다시
> 설계하는 데 토큰이 가장 많이 든다. 아래는 **몸판 라인 22개 + 플레어 Ⓖ 를 실제로 만들면서
> 굳은 순서**다. 새로 생각하지 말고 이걸 따른다.

## 0. 시작 (세션 비용 최소)

1. `docs/STATUS.md` 한 장을 읽는다. **CLAUDE.md 외에 다른 건 아직 열지 않는다.**
2. `docs/book/INDEX.md` 에서 그 쪽의 노트가 이미 있는지 본다. **있으면 이미지를 열지 않는다.**

## 1. 판독 (이미지는 최소로)

- **라인당 대표 1쪽만** 연다. 세부 수치는 그 라인을 실제로 구현할 때 연다.
- 숫자 하나가 필요하면 전체 쪽이 아니라 `python3 tools/bookpage.py crop <쪽> x0 y0 x1 y1 [배수]`.
- 읽은 즉시 `docs/book/PNNN.md` 에 남긴다 — **확정 수치**와 **미확정 항목을 분리해서**.
  지어내지 않는다. 모르면 "미판독"이라고 쓴다.
- 꼬리말의 `…P.NNN` 참조를 반드시 적는다. 교재는 그걸로 연산을 가리킨다.

## 2. 무엇이 필요한지 판정

[docs/book/P157.md](book/P157.md) 의 **처리 방법 7개 대조표**와 맞춰 본다.

| 있는 것 | 없는 것 |
|---|---|
| 160 닫는다 · **161 닫는다·벌린다**(`designFlare`) · 163 기준점 벌림 | **157 맞댄다** · 158 맞대면서 벌린다 · 159 2곳 이상 맞댄다 · 162 평행 절개 |

- 필요한 연산이 **있으면** → 4번으로.
- **없으면** → 카탈로그에 **`blockedBy` 로 이유를 적고 보류**한다. 억지로 만들지 않는다.
  보류 사유가 없으면 "그냥 아직 안 함"과 구별이 안 돼 다음 세션이 근거 없이 착수한다.

## 3. 카탈로그 슬롯

`js/*Presets.js` 에 family → variant 슬롯을 **전부** 만든다(실행 가능한 것만이 아니라).
그래야 "무엇이 남았는가"가 코드에 있다. 실행 가능한 것만 `availVariant`.

## 4. 순수 연산 (필요할 때만)

- 새 모듈은 **순수 함수**: DOM·render·storage 미접근, 입력 불변, 실패는 `reason` 으로 throw.
- **이미 검증된 코드를 재사용한다** — ring 구성·정확 분할은 `designLineTool` 에 있다.
  베끼면 한쪽만 고쳐도 조용히 어긋난다.
- ★ **포맷 경계**: geometry 는 `{kind:"path", commands:[M,C…]}`. `{kind:"cubic"}` 은 패턴선
  포맷이라 renderer 가 `invalid-primitive` 로 깨진다. **내보낼 때 반드시 되돌린다.**
  (이 함정에 세 번 걸렸다.)

### 불변식을 먼저 정한다 — 이게 검증의 전부다
실제로 버그를 잡아 준 것들:
- **강체 회전 → 면적 정확 보존**(플레어: 해석값 ½·r²·sinθ 와 소수점까지 일치)
- **회전은 길이를 안 바꾼다** → 진동둘레·옆선 길이 불변
- **폐곡선 연결 오차 ~1e-15 · 자기교차 0**(제1법칙: 우리는 종이 위에 있다)
- **비대칭에서 남는 잔여는 감추지 않고 기록**(뒤 어깨다트 0.103cm)

## 5. 하네스

`test/harness/*Check.js` — 픽스처 + 위 불변식 + **실패 계약(거부 사유)**. `runAll.js` 에 등록.
**shape/perf 골든은 건드리지 않는다.**

## 6. 프리셋 레코드

교재 수치를 그대로. **함께 필요한 파라미터를 빠뜨리지 않는다** —
예: 플레어 Ⓖ 는 `waistDartScales` 0 이 없으면 절개선이 다트를 관통한다.
(실패 사례: Ⓑ·Ⓒ·Ⓓ 에 밑단을 안 줘서 «밑단 +1» 이 조용히 무시됐다.)

## 7. UI 배선 — **별도 커밋**

엔진 변경과 UI 변경을 같은 커밋에 섞지 않는다. 캐시 버전(`?v=`)을 올린다.

## 8. 검증 (순서 고정)

```bash
node test/harness/runAll.js          # 전체 통과
git status --porcelain test/harness/golden/   # 비어 있어야 한다
```
그다음 **sandbox**(`http://127.0.0.1:8420/sandbox.html`)에서 실제 도안으로:
```js

```
- **숫자로 먼저 본다.** 스크린샷은 마지막 1장.
- 콘솔 오류 0 · `SB.storageKeys()` 0 · reference frozen 확인.
- ⚠ **콘솔·캐시 잔여를 현재 오류로 오판하지 말 것** — 새 탭으로 구분한다(두 번 걸렸다).

---

## ⚠ 하의(바지·스커트)는 이 레시피의 4~6번이 그대로 안 맞는다

지금까지 쌓은 것은 전부 **상의 원형**(B·W·BL·진동·다트 a~f) 위에 있다. 바지·스커트는
**원형 자체가 다르다**(허리·엉덩이·밑위). 그래서:

- **옮겨 가는 것**: 단계 구조(원형 완료본 → 복사 → 디자인 → 체크포인트 → 통합 결과),
  세션 스냅샷·hash 종속·stale 판정, 카탈로그·`blockedBy`, 하네스·골든 규율, 처리 방법 연산.
- **다시 만들어야 하는 것**: 하의 원형 제도(`draft.js` 급), 그 조각의 의미 모서리(`edge`),
  계측(허리·엉덩이·밑위), 완료 게이트.

**착수 전에 "하의 원형을 어디서 가져오는가"부터 정해야 한다** — 상의 원형처럼 [학교책]
기준인지, 교재별로 다른지. 그게 정해지기 전엔 코드를 시작하지 않는다.
