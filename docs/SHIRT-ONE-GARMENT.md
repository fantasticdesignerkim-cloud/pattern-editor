## 2. 제작 차단 버그 — 새 선 «그리기 완료»가 다른 조각의 합성 외곽을 지움

> **✅ 2026-11-10 수정(김님 «수정 진행» 승인 · 미커밋)** — 아래 제안 1·2·3·4·5 그대로 구현(`designLineTool.js` `invalidateForLine`·`recomposeReflectedPiece` · 캐시 `?v=2026111001`).
> 검증: `projectFileCheck` 113/113(§1 반전 · §7 신규 — 옛 코드에선 실패) · 선 도구 관련 13 스위트 통과 · 격리 UI 실측(앞 선 완료 → 뒤 반영 보존 · 소매 선 완료 → 몸판·소매 «변경됨» 없음). 아래는 조사 당시 기록.

**독립 재현(실제 마우스)**: 1–7b·완료 뒤 소매 안에 보조선 2점 → `그리기 완료` →
`designOutline` {front,back} → **없음** · `isCurrentBodiceChanged` false → **true** · `isCurrentSleeveChanged` false → **true**
(몸판 변경 → 소매·카라·Design 연쇄 «변경됨»). 화면상 곡선 밑단이 사라진다. `디자인 외곽 합성`(btnDesignCompose)을 다시 눌러야 복구(둘 다 false).
몸판 안에서도 같은 일: 앞 선을 그리는 순간 뒤판 반영이 지워졌다(4번).

**원인(코드)**: `js/designLineTool.js` `invalidateParts(p)` 가 **어떤 선이든** `parts=[]`·`boundaryPreview=null`·`designOutline=null`.
호출처: `commitDraft`(새 선 — 역할은 항상 guide), `setRole`, `deleteSelected`, 편집 끝(`endDrag` 의 cut/guide 분기), `revalidate`.
그런데 `designOutline` 은 **앞·뒤판 boundary 선 + geometry 만의 함수**(`composeForPiece`)라 guide·cut·소매 선은 입력이 아니다.
`parts` 는 `sourceCutId`, `boundaryPreview` 는 `sourceLineId` 출처를 이미 들고 있다.

**두 번째 증상(판정 캐시)**: `doComposeDesignOutline` 은 `rerender()` 만 부르고 `seamStateCache=null`·`syncCutStatus()`·`notifyDesignResult()` 를
부르지 않는다(`doReflectToBodice` 는 부른다) → 복구 뒤에도 선택 선의 «판정 보류» 가 재클릭 전까지 남는다(코드 근거 · 이번 재현은 연결 안 된 선이라 «invalid» 로만 확인).

**최소 수정 제안(아직 수정 안 함)** — `designLineTool.js` 한 파일:
1. `invalidateParts(p, line)` 를 출처 기준으로 좁힌다:
   `parts` = `sourceCutId === line.id` 인 것만 제거 · `boundaryPreview` = `sourceLineId === line.id` 일 때만 · `designOutline` = 건드리지 않음.
2. 앞·뒤판 **boundary 가 관여**한 경우만(역할이 boundary 로/에서 바뀜 · boundary 삭제) 기존 `composeWith`/`recomposeDesignOutline` 로 **재합성**
   (실패하면 사유 표시 + 그때만 null — 사용자 자신의 그 조각 조작이므로 정당한 무효화).
3. `commitDraft`(새 선=guide)는 형상 입력이 없으므로 파생 무효화 없음.
4. `revalidate`(geometry 재계산 경로)는 **현행 유지**(정당한 하위 무효화).
5. `doComposeDesignOutline` 성공 뒤 `seamStateCache=null; syncCutStatus(); notifyDesignResult();` 추가.

**영향**: 엔진·골든 무관(UI 도구 상태). `projectFileCheck` §1 «(기존 동작)» 단언(L144–145)은 반대로 바꿔야 한다 —
보존을 단언하도록. `designLineToolCheck`·`bodyReflectCheck`·`boundaryPreviewCheck`·`sleevePartSplitCheck` 가
«새 선/역할 변경 → parts 비움»을 단언하는지 수정 전에 확인 필요. 앞여밈(`frontPlacket`)은 designOutline 이 지워져도
남아 있어 옛 외곽 기준과 어긋날 수 있었다 — 수정하면 그 어긋남 경로도 사라진다.

| Ⓐ 소맷부리 | 소매 밑선을 소맷부리까지 수직 → **소맷부리 = 소매 폭**(B83: 32.07, [P041](book/P041.md) 실측) | P.40 |

### 6.2 확정 (김님 · 2026-11-10 · 원문 그대로)

> «손목 둘레 + 여밈량(2) + 여유량(2), 커프스와 만나는 부분은 셔링으로 처리»

- 소매 = **Ⓐ**(Ⓣ 게이트 완화 안 함).
- **입력 3개 — 서로 독립, 각각 수정 가능**
  - 손목 둘레 `Wrist`: 실제 사용자 값은 **아직 미확정**. 책 참고값 16(P.8)은 예시로만 쓴다.
  - 여밈량 `Overlap` = 2
  - 여유량 `Ease` = 2
- **세 값은 다른 것을 뜻한다 — 섞지 않는다**

  | 이름 | 식 | 손목 16일 때(예시) | 뜻 |
  |---|---|---|---|
  | **커프스 가로(재단 기준 길이)** | Wrist + Overlap + Ease | **20** | 커프스 조각의 긴 변 |
  | **단추 잠근 둘레** | Wrist + Ease | 18 | 몸에 두르는 완성 둘레. 여유 2는 여기에만 들어간다 |
  | **여밈 부위** | Overlap | 2 | 겹치는 부분. 몸 둘레 여유가 아니다 |

- **소맷부리 = 셔링**(턱 아님). 셔링 분량 = Ⓐ 소맷부리 − 커프스 달림선 길이. 달림선 길이는 아래 미정 항목 «달림법 A/B»에 따라 갈린다.
  - **여밈 2를 달림선에 자동으로 넣지 않는다.**
  - 손목 16 · B83 Ⓐ 소맷부리 32.07 기준 참고값(트임 분량은 빼지 않음): A면 32.07 − 20 = **12.07**, B면 32.07 − 18 = **14.07**.
- 종전 제안(K1 19/24, K4 개더/턱, K5 폭 3·여밈 1.5)은 **이 설정으로 대체**한다.
- **커프스 완성 폭 = 3cm**(김님 «오키», 2026-11-10 · P.91 도해 «3» · 수정 가능 입력).
- **트임 = P.91 ④ 덧단(뾰족단)**(김님 «4번 덧단으로», 2026-11-10).
  - 트임 길이 **10은 책 기본값**이다. 수정 가능한 입력이고, 고정 공식으로 다루지 않는다.
  - 책 ④의 커프스 여밈분 1은 **김님 여밈 2로 대체**한다.
  - **덧단 자체 폭(책 2)과 커프스 여밈(2)은 다른 값이다.** 숫자가 같아도 입력을 공유하지 않는다.
- **책과의 관계(사실 기록 · 재질문 아님)**
  - 책(P.91)은 «손목 + 3 이상» + 여밈분 1.5다. 김님 설정은 잠근 둘레 = 손목 + 2 · 여밈 2이고, **김님 설정이 우선**한다.
  - 잠근 둘레(손목 + 2)는 손바닥 + 3보다 작다. 책 규칙상 **트임은 필수**이고, 정할 것은 트임의 방식·위치·길이뿐이다.
- **표기 대조(참고)**: P.44 Ⓗ 커프스 끝의 «1»은 P.91 표기상 여밈분일 가능성이 있다. 형상 영향은 없고 퍼프 소매를 다룰 때 확인한다.

### 6.3 확정 (김님 최종 답, 2026-11-10 — 종전 미확정 U1~U4 해소)

- U1 커프스 = **한 장 접기**(완성 폭 3 · 펼친 폭 6 · 시접 별도 없음).
- U2 입력 소매길이 = **커프스 포함**(52 → 소매 본체 49 + 커프스 3).
- U3 트임 위치 = 소맷부리 위 **소매 중심선 → 뒤 옆선 구간의 1/2**(뒤 반폭 가운데).
- U4 **여밈 2까지 소매를 붙임**(P.91 방법 A) → 달림 = 커프스 가로 전체.
- U5 손목 = 책 참고값 16(P.8)으로 시작하고 «실측 아님»으로 표시한다(김님 실측값은 아직 없음).
- 곡선 소맷부리(Ⓐ 이외)에서의 기준선·호 해석은 범위 밖이다. 지금은 **Ⓐ 직선 소맷부리만** 지원한다.

### 6.4 선택된 ④ 덧단(뾰족단) 도해 상세 — P.91 ④ (읽기 전용 크롭)

본문(F): «가위집을 넣고 **뒤쪽은 바이어스로, 앞쪽은 직사각형의 가는 천으로** 마무리. 덧단 끝을 삼각으로 해서 **뾰족단**이라고 한다.»

| 표기 | 위치 | 읽기 |
|---|---|---|
| **10** | 소맷부리 → 덧단 뾰족 끝(호 표시) | 트임(덧단) 완성 길이 — 책 기본값, 수정 가능(F) |
| **2** | 소맷부리 쪽 덧단 두 선 사이 | **덧단(앞쪽 가는 천) 완성 폭** (F) |
| **1**(위) | 삼각 끝 | 뾰족 끝 삼각 높이 (I — 화살 위치상) |
| **1.5** | 삼각 아래 두 점선 사이 | 덧단 윗부분 가로 박음(고정 박음) 위치·간격 (I) |
| **0.1** | 덧단 가장자리 | 끝 박음(상침) 간격 (F 표기 · 봉제 지시) |
| **1**(단면도) | 소맷부리 아래 단면 | 뒤쪽 바이어스 완성 폭 (I) |
| 점선 호 2개 + «개더» | 트임 양옆 소맷부리 | 트임 양쪽 소맷부리를 줄여(우리는 셔링) 커프스에 단다 (F) |
| 커프스 «손목 둘레+3 · 여밈분 1 · 3» | 아래 직사각형 | ④용 책 값 → **김님 설정으로 대체**(손목+2+2 · 폭 3) |

- 가위집(실제로 자르는 선) 끝의 위치는 **표기가 없다**. 10은 덧단 끝까지다.
- 덧단 조각(앞쪽 가는 천)과 바이어스 조각의 **재단 치수(시접·접는 분량)는 책에 없다** → 2차(재단)에서 정한다.
- 1차에서는 소매 위의 **트임 선 + 덧단 완성 윤곽(폭 2 · 길이 10 · 뾰족 끝)을 표시**만 한다. 별도 재단 조각으로 만들지 않는다.

### 6.5 구현 (2026-11-10 · 미커밋) — `designCuff` + 소매 Ⓐ 연결

- **엔진(순수)**: `js/designCuff.js`
  - 독립 커프스 폐곡선 4변(소매 달림 · 여밈 끝 · 바깥 · 끝)과 구성선(접는선 y=3 · 여밈선 x=가로−2).
  - 트임 ④ 덧단 완성선: 트임선에서 소매 중심 쪽으로 폭 2 · 길이 10 · 뾰족 끝 1.
  - 길이를 따로 낸다: 가로 20 · 잠근 둘레 18 · 달림 20(방법 A) · 소맷부리 실측 32.07 · 셔링 = 소맷부리 − 달림(실측 12.07).
  - 모순 입력은 사유와 함께 거부하고 자동으로 보정하지 않는다: 셔링 없음 · 트임이 위팔선을 넘음 · 덧단이 중심선을 넘음 · 확정 사양 밖(두 장 · 방법 B · 기장 미포함 · 다른 트임) · 값 범위.
- **연결**: `sleeveAApply.draftWith`가 본체를 «입력 − 완성 폭»으로 Ⓐ 제도하고(Ⓐ 엔진·보호 파일 무변경), 그 결과에서 커프스를 만든다.
  - `working.sleeveA.parameters.cuff` · `working.sleeveA.cuff` → `sleeveCheckpoint`: 재제도 일치 검사(`cuff-mismatch`) → `sleeveResult.inputs.cuff` · `sleeveResult.cuff`(출처 P.91 · geometry · 길이). 서명에 포함된다.
  - designResult와 프로젝트 파일은 기존 경로 그대로 따라온다.
  - 커프스가 있는 소매는 외곽 수동 수정 완료를 거부한다(`manual-edit-with-cuff`).
- **커프스 OFF**: 상태·geometry·완료본·hash가 HEAD와 바이트 단위로 같다(하네스가 HEAD 모듈과 직접 비교).
- **표시**: 소매 근처 소맷부리 아래에 커프스 조각 · 접는선 · 여밈선 · 겉/안 3 · 달림·셔링·가로식 · 잠근 둘레를 그린다. 소매 위에는 덧단 완성선 · 트임 위치점 · «중심→뒤 옆선 1/2»을 그린다.
  - `pointer-events:none`이고 소매 hit bbox 밖이라 선 도구가 소매로 오인하지 않는다.
  - fit·카라 자동 배치는 커프스 범위를 포함한다.
- **UI**: 소매 탭 Ⓐ 선택 시 «커프스·트임 (P.91 ④ 덧단)» 체크(기본 꺼짐)와 입력 7칸(손목 · 여밈 · 여유 · 완성 폭 · 트임 길이 · 덧단 폭 · 뾰족 끝).
- **덧단·바이어스 재단 조각은 만들지 않았다.** P.91 ④ 도해는 완성 치수(폭 2 · 길이 10 · 끝 1)와 봉제 지시(0.1 · 1.5 · 바이어스 1)뿐이고, 재단 치수(접는 분량 · 시접 · 바이어스 재단 폭)가 없다 → **질문 1개**(아래).
- **질문(김님)**: 덧단(앞쪽 가는 천)·뒤쪽 바이어스를 재단 조각으로 만들 때 접는 분량·시접·바이어스 재단 폭은 어떤 값으로 할까요? (책에 없음 · 2차 재단 단계로 미뤄도 됨)
- **남은 한계**
  - 커프스 양 끝의 앞/뒤(트임 어느 쪽에 여밈이 오는지)와 단추 위치는 표시하지 않는다(책 표기 없음).
  - 가위집 끝은 그리지 않는다.
  - 덧단·바이어스가 소맷부리 봉제 길이에 주는 영향은 반영하지 않는다(소맷부리 실측 그대로).
  - 320px 폭에서는 캔버스 설명 글자가 빽빽하다(값은 소매 탭 정보 줄에 있음).

### 6.6 (참고) 착수 전 연결 설계 — 위 6.5 로 구현됨

1. **입력 위치**: `working.sleeveA.parameters`(지금은 `{ sleeveLengthCm }`, `sleeveAApply.stateOf`)에 `cuff`를 더한다.
   ```
   cuff: {
     wristCm,                 // U5 — 기본 16(책 참고값 표시)
     overlapCm: 2, easeCm: 2, // 김님 확정 · 수정 가능 · 서로 독립
     widthCm: 3,              // 김님 확정 · 수정 가능
     construction: null,      // U1 "fold-one" | "two-piece" — 미정이면 완료 차단
     attachOverlap: null,     // U4 true(A) | false(B) — 미정이면 완료 차단
     includeInSleeveLength: null, // U2 — 미정이면 완료 차단
     vent: { type: "placket-pointed", lengthCm: 10, placketWidthCm: 2, tipCm: 1, positionCm: null /* U3 */ }
   }
   ```
   - 이름은 `vent`·`placketWidthCm`로 하고, 몸판 앞여밈 `designPlacket` / `working.frontPlacket`과 **이름·코드를 공유하지 않는다**(다른 부위·다른 의미).
   - **`cuff`가 없으면 지금 Ⓐ와 결과가 비트 단위로 같다**(기존 저장 파일·하네스 호환).
2. **새 순수 모듈** `designCuff.js`
   - 입력: Ⓐ `sleeveResult` 이전의 geometry(읽기만)와 `cuff`.
   - 출력:
     - `cuffPiece`: 폐곡선 — 가로 = 손목 + 여밈 + 여유, 세로 = 폭(접기면 ×2 + 접힘선 표시). 여밈 구간을 표시한다.
     - `vent`: 소매 위 표시선 — 트임 선 + 덧단 윤곽.
     - `lengths`: `{ cuffLengthCm, closedCircumferenceCm, attachLengthCm, sleeveHemCm, shirringCm }`
   - **셔링 검증**: `shirringCm = sleeveHemCm − attachLengthCm > 0`. 트임이 있어도 소맷부리 길이는 그대로다(가위집이라 천이 빠지지 않는다 — I, ①과 다름).
   - **트임 필수 검증**: 잠근 둘레 < 손바닥 + 3이면 트임이 있어야 한다(지금은 ④ 선택이라 충족).
3. **완료본 연결**: `sleeveCheckpoint.checkA`가 `designCuff`를 다시 계산해 일치를 확인한다. `completeA`의 `result`에 `inputs.cuff` · `cuff:{ piece, vent, lengths, source:{ page:91, method:"placket-pointed(④)", userSettings:[…] } }`를 더한다.
   - 기존 서명 함수가 result 전체를 hash하므로 소매 «변경됨» → 카라·Design 전파는 **자동**이다.
   - `designResult.sleeve`는 이미 sleeveResult를 참조하므로 **추가 작업이 없다**.
   - `projectFile`은 `working` 전체를 저장하고, 상태는 기존 hash로 확인하므로 **새 저장 형식이 없다**. 복원 왕복만 하네스에 넣는다.
4. **기장(U2)**: «포함»이면 Ⓐ 재제도에 `sleeveLengthCm − widthCm`를 넘긴다. Ⓐ 엔진은 그대로이고 입력만 바뀐다. «미포함»이면 그대로 둔다.
5. **UI**: Ⓐ 소매 패널에 입력 칸을 둔다(손목·여밈·여유·폭·트임 길이·덧단 폭은 각각 별도 칸, U1~U4 선택). 미정인 동안 «미정» 표시와 완료 비활성. 소매 옆에 커프스 조각 렌더 + 세 길이 표시. 엔진 커밋 → UI 커밋 순서로 나눈다.
6. **하네스**: 세 길이 산식 분리(여밈이 잠근 둘레·덧단 폭에 섞이지 않는지) · A/B 달림선 · 셔링 > 0 · 미정 시 완료 차단 · `cuff` 없는 Ⓐ 비트 동일 · 저장/복원 왕복 · 변경 전파.
7. **범위 밖(2차)**: 덧단·바이어스·커프스 재단 조각(시접·접는 분량) · 너치(커프스 여밈 시작점·트임 위치) · 단추·단춧구멍 · 식서 · 재단 수량.
